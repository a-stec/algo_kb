# Быстрая сортировка: лекционная заметка и практические задания

## 1. Что такое быстрая сортировка

**Быстрая сортировка**, или **quicksort**, — это алгоритм сортировки сравнением, основанный на принципе **“разделяй и властвуй”**.

Основная идея:

1. Выбирается **опорный элемент** — `pivot`.
2. Массив разбивается на две части:

   * элементы меньше pivot;
   * элементы больше pivot.
3. Затем те же действия рекурсивно выполняются для левой и правой части.
4. Когда подмассив имеет размер `0` или `1`, сортировать его уже не нужно.

Общая схема:

```text
quicksort(array):
    выбрать pivot
    разделить массив относительно pivot
    отсортировать левую часть
    отсортировать правую часть
```

Главная особенность quicksort: после разбиения отдельного этапа “слияния” обычно нет. В отличие от сортировки слиянием, quicksort заранее переставляет элементы так, что левая и правая части уже находятся на своих местах относительно pivot.

---

## 2. Почему quicksort относится к “разделяй и властвуй”

Метод **“разделяй и властвуй”** обычно состоит из трёх шагов:

1. **Разделить** задачу на меньшие подзадачи.
2. **Решить** эти подзадачи тем же способом.
3. **Объединить** результат.

В quicksort это выглядит так:

| Этап             | Что происходит в quicksort                                      |
| ---------------- | --------------------------------------------------------------- |
| Разделение       | Массив разбивается относительно pivot                           |
| Решение подзадач | Левая и правая части сортируются рекурсивно                     |
| Объединение      | Отдельного слияния обычно нет: части уже стоят на нужных местах |

> В quicksort ключевая работа происходит до рекурсивных вызовов — на этапе partition. После рекурсивной сортировки левой и правой частей массив уже оказывается отсортированным.

---

## 3. Является ли quicksort сортировкой обменами

Quicksort можно отнести к сортировкам, использующим **обмены элементов**, потому что во время partition элементы меняются местами.

> Bubble sort и quicksort можно отнести к сортировкам, в которых используются обмены элементов. Но идея у них разная: bubble sort работает через локальные обмены соседних элементов, а quicksort — через разбиение массива относительно pivot.

Сравнение:

```text
Bubble sort:
- сравниваем соседние элементы;
- если стоят неправильно, меняем местами;
- крупные элементы постепенно “всплывают” к концу массива.

Quicksort:
- выбираем pivot;
- глобально разбиваем диапазон;
- рекурсивно сортируем части.
```

То есть общий низкоуровневый приём — обмен элементов — у них есть. Но quicksort не является “улучшенным пузырьком”.

---

## 4. Что такое partition

**Partition**, или разбиение, — это центральная операция quicksort.

Её задача:

> Переставить элементы так, чтобы относительно pivot массив оказался разделён на части: меньшие элементы с одной стороны, большие — с другой.

Например:

```text
[7, 2, 9, 4, 3, 8, 5]
```

Пусть pivot = `5`.

После partition может получиться:

```text
[2, 4, 3, 5, 9, 8, 7]
```

Важно: после partition не обязательно весь массив отсортирован. Гарантируется только разбиение относительно pivot.

---

## 5. Схема Ломуто

Схема Ломуто — один из простых вариантов partition.

Обычно pivot выбирается как последний элемент диапазона.

Пример:

```text
[7, 2, 9, 4, 3, 8, 5]
```

```text
pivot = 5
```

Идея схемы Ломуто:

* один указатель `j` проходит по массиву;
* второй указатель `i` показывает границу зоны элементов, которые меньше pivot;
* если текущий элемент меньше pivot, он меняется местами с элементом на границе;
* в конце pivot ставится между меньшими и большими элементами.

Псевдокод:

```text
partition_lomuto(A, low, high):
    pivot = A[high]
    i = low

    for j from low to high - 1:
        if A[j] < pivot:
            swap A[i], A[j]
            i = i + 1

    swap A[i], A[high]
    return i
```

После этого pivot оказывается на своей окончательной позиции.

Примерная структура после partition:

```text
элементы < pivot | pivot | элементы >= pivot
```

Особенность:

> В схеме Ломуто pivot обычно действительно становится на финальное место после одного partition.

Но есть нюанс с условием:

```text
A[j] < pivot
```

или

```text
A[j] <= pivot
```

Если использовать `<=`, равные pivot элементы будут уходить в левую часть. На массивах с большим количеством одинаковых элементов это может ухудшать работу алгоритма. Поэтому для таких случаев часто рассматривают трёхпутевое разбиение.

---

## 6. Схема Хоара

Схема Хоара использует два указателя:

* левый указатель идёт слева направо;
* правый указатель идёт справа налево.

Они двигаются навстречу друг другу и ищут элементы, которые стоят “не на своей стороне” относительно pivot.

Идея:

```text
слева ищем элемент, который должен быть справа;
справа ищем элемент, который должен быть слева;
если нашли такую пару — меняем местами.
```

Упрощённый псевдокод:

```text
partition_hoare(A, low, high):
    pivot = A[(low + high) // 2]
    i = low - 1
    j = high + 1

    while true:
        repeat:
            i = i + 1
        until A[i] >= pivot

        repeat:
            j = j - 1
        until A[j] <= pivot

        if i >= j:
            return j

        swap A[i], A[j]
```

Результат:

```text
элементы <= pivot | элементы >= pivot
```

Важное отличие от Ломуто:

> В схеме Хоара возвращается не обязательно финальная позиция pivot, а граница разбиения.

## 7. Выбор pivot

От выбора pivot сильно зависит эффективность quicksort.

Возможные способы выбора pivot:

1. Первый элемент.
2. Последний элемент.
3. Средний элемент по индексу.
4. Случайный элемент.
5. Медиана из трёх.
6. Более сложные стратегии.

### Первый или последний элемент

Плюс:

```text
просто реализовать
```

Минус:

```text
на уже отсортированных или обратно отсортированных массивах может дать худший случай
```

Например, массив:

```text
[1, 2, 3, 4, 5, 6, 7]
```

Если pivot всегда последний, то каждый раз выбирается максимальный элемент.

Разбиение получается:

```text
левая часть: n - 1 элементов
правая часть: 0 элементов
```

Это плохой случай.

### Средний элемент по индексу

Выбор среднего элемента по индексу может хорошо работать на уже отсортированных и обратно отсортированных массивах.

Например:

```text
[9, 8, 7, 6, 5, 4, 3, 2, 1]
```

Средний элемент — `5`. Это хороший pivot, потому что он близок к медиане значений.

Но важно:

> Средний по индексу элемент не всегда является хорошим pivot.

Например:

```text
[100, 1, 2, 999, 3, 4, 5]
```

Средний по индексу элемент — `999`, но почти все элементы меньше него. Разбиение получится неудачным.

### Случайный pivot

Случайный pivot уменьшает вероятность систематического попадания в худший случай.

Важно:

> Случайный pivot не делает худший случай невозможным, но делает его маловероятным на практике.

### Медиана из трёх

Берутся три элемента:

```text
первый
средний
последний
```

Из них выбирается медиана.

Например:

```text
[9, 1, 5]
```

Медиана — `5`.

Этот способ часто лучше, чем выбор первого или последнего элемента, потому что снижает риск выбрать слишком маленький или слишком большой pivot.

## 8. Сложность quicksort в хорошем случае

В хорошем случае pivot каждый раз делит массив примерно пополам.

Например:

```text
n
n/2          n/2
n/4  n/4    n/4  n/4
...
```

Количество уровней рекурсии примерно равно:

```text
log₂ n
```

Почему?

Потому что мы постоянно делим размер задачи пополам:

```text
16 → 8 → 4 → 2 → 1
```

Для `16` это `4` деления, потому что:

```text
log₂ 16 = 4
```

На каждом уровне рекурсии суммарно обрабатывается примерно `n` элементов.

Первый уровень:

```text
n
```

Второй уровень:

```text
n/2 + n/2 = n
```

Третий уровень:

```text
n/4 + n/4 + n/4 + n/4 = n
```

И так далее.

Получается:

```text
работа на одном уровне ≈ n
количество уровней ≈ log n
итого: O(n log n)
```

> Если pivot каждый раз делит массив примерно пополам, то на каждом уровне рекурсии partition суммарно просматривает около `n` элементов, а уровней получается около `log n`. Поэтому сложность quicksort в хорошем и среднем случае — `O(n log n)`.

---

## 9. Сложность quicksort в худшем случае

Худший случай возникает, когда pivot каждый раз оказывается минимальным или максимальным элементом текущего подмассива.

Тогда разбиение получается неравномерным:

```text
0 элементов | pivot | n - 1 элементов
```

или

```text
n - 1 элементов | pivot | 0 элементов
```

Вместо дерева получается “лестница”:

```text
n
n - 1
n - 2
n - 3
...
1
```

Работа:

```text
n + (n - 1) + (n - 2) + ... + 1
```

Эта сумма даёт:

```text
O(n²)
```

> В худшем случае quicksort не делит массив на две примерно равные части. Каждый раз отсекается только один элемент, а оставшаяся часть почти такого же размера. Поэтому глубина рекурсии становится `n`, а суммарная работа — `O(n²)`.

Пример худшего случая:

```text
[1, 2, 3, 4, 5, 6, 7]
```

Если pivot всегда последний элемент, то он каждый раз максимальный.

---

## 10. Сложность по памяти

Quicksort обычно работает **на месте**, то есть не требует дополнительного массива размера `n`.

Но память нужна для стека рекурсии.

| Случай          | Память     |
| --------------- | ---------- |
| Хороший/средний | `O(log n)` |
| Худший          | `O(n)`     |

Почему?

В хорошем случае глубина рекурсии примерно `log n`.

В худшем случае рекурсия превращается в цепочку длиной `n`.

---

## 11. Устойчивость quicksort

Сортировка называется **устойчивой**, если равные по ключу элементы сохраняют свой относительный порядок.

Пример:

```text
[(5, "A"), (3, "B"), (5, "C")]
```

Сортируем только по числу.

В устойчивой сортировке результат должен сохранить порядок `"A"` перед `"C"`:

```text
[(3, "B"), (5, "A"), (5, "C")]
```

Классическая quicksort обычно **неустойчива**.

Она может получить:

```text
[(3, "B"), (5, "C"), (5, "A")]
```

Потому что во время partition элементы меняются местами, и равные элементы могут переставиться относительно друг друга.

> Классическая in-place quicksort обычно неустойчива, потому что обмены во время partition могут нарушить относительный порядок равных элементов.

Важно:
> Устойчивую quicksort можно реализовать, но обычно ценой дополнительной памяти или усложнения алгоритма.

---

## 12. Адаптивность quicksort

Сортировка называется **адаптивной**, если она умеет использовать уже имеющуюся упорядоченность данных.

Например, insertion sort хорошо работает на почти отсортированных массивах.

Классическая quicksort обычно **неадаптивна**.

Это можно объяснить так:

> Quicksort не “понимает”, что массив уже отсортирован. Она всё равно выбирает pivot, выполняет partition и запускает рекурсию.

Более точная формулировка:

> Классическая quicksort не использует сам факт предварительной отсортированности массива. Более того, при плохом выборе pivot уже отсортированный массив может привести к худшему случаю `O(n²)`.

Пример:

```text
[1, 2, 3, 4, 5, 6, 7]
```

Если pivot всегда последний, он каждый раз максимальный.

Получается плохое разбиение:

```text
n - 1 элементов | pivot | 0 элементов
```

---

## 13. Кэш-локальность

Quicksort часто быстра на практике не только из-за средней сложности `O(n log n)`, но и из-за хорошей **локальности кэша**.

Процессор обычно не загружает из оперативной памяти каждый элемент отдельно. Он загружает блок соседних данных — кэш-линию.

Массив расположен в памяти непрерывно:

```text
A[0], A[1], A[2], A[3], ...
```

Когда алгоритм последовательно проходит по массиву, соседние элементы уже могут находиться в кэше процессора.

Quicksort хорошо подходит для массивов, потому что:

1. partition обычно последовательно проходит по непрерывному участку массива;
2. сортировка часто выполняется на месте;
3. рекурсия постепенно переходит к меньшим подмассивам, которые могут лучше помещаться в кэш.

Хорошая формулировка:

> Quicksort часто хорошо работает на практике, потому что partition обрабатывает непрерывные участки массива, а это хорошо согласуется с работой кэша процессора.

Но есть нюанс:

> Для очень маленьких подмассивов quicksort может быть не лучшим вариантом из-за накладных расходов на рекурсию и partition. Поэтому реальные реализации часто переключаются на insertion sort для маленьких диапазонов.

## Задание 4. Проверка устойчивости сортировки

Дан массив объектов:

```text
[(5, "A"), (3, "B"), (5, "C"), (2, "D"), (5, "E")]
```

Сортировать нужно только по первому значению.

То есть ключ сортировки:

```text
5, 3, 5, 2, 5
```

Идентификаторы `"A"`, `"C"`, `"E"` нужны для проверки порядка равных элементов.

Нужно:

1. реализовать сортировку по числовому ключу;
2. после сортировки проверить порядок элементов с ключом `5`;
3. определить, сохранился ли порядок `"A"`, `"C"`, `"E"`;
4. сделать вывод, устойчива ли реализация.

Ожидаемый порядок для устойчивой сортировки:

```text
(5, "A") перед (5, "C") перед (5, "E")
```

Если после сортировки получилось, например:

```text
(5, "E"), (5, "A"), (5, "C")
```

то сортировка неустойчива.

### Как написать проверку устойчивости

Идея:

1. У каждого элемента есть ключ и исходный номер.
2. После сортировки элементы с одинаковым ключом должны идти в порядке возрастания исходных номеров.
3. Если для какого-то ключа порядок исходных номеров нарушен, сортировка неустойчива.

Пример данных:

```python
arr = [
    (5, "A", 0),
    (3, "B", 1),
    (5, "C", 2),
    (2, "D", 3),
    (5, "E", 4),
]
```

После сортировки по первому полю нужно проверить элементы с ключом `5`.

Было:

```text
A -> C -> E
```

Если осталось:

```text
A -> C -> E
```

то для этих элементов порядок сохранён.

Если стало:

```text
C -> A -> E
```

то порядок нарушен.

### Как реализовать трёхпутевой quicksort

Реализовать quicksort с тремя зонами:

```text
< pivot
= pivot
> pivot
```

Можно использовать три указателя:

```text
lt — граница зоны меньше pivot
i  — текущий элемент
gt — граница зоны больше pivot
```

Общая идея:

```text
while i <= gt:
    if A[i] < pivot:
        swap A[lt], A[i]
        lt += 1
        i += 1
    elif A[i] > pivot:
        swap A[i], A[gt]
        gt -= 1
    else:
        i += 1
```

После partition:

```text
A[low ... lt-1]     < pivot
A[lt ... gt]        = pivot
A[gt+1 ... high]    > pivot
```

Рекурсивно сортируются только зоны:

```text
< pivot
> pivot
```

Зону `= pivot` сортировать не нужно.

Проверить на массивах:

```text
[5, 3, 5, 5, 2, 5, 1, 5, 4]
[3, 3, 3, 3, 3]
[1, 2, 3, 4, 5]
[5, 4, 3, 2, 1]
[4, 1, 4, 2, 4, 3, 4]
```

> На каких данных трёхпутевая quicksort особенно эффективна?
